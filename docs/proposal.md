## 2. 기획 배경

### 해결하려는 한국외대의 현안: "같은 질문에도 학생마다 정답이 다르다"

한국외대의 학사 규정은 **입학년도·캠퍼스·소속 대학·전공 이수 유형·학적 상태(신입/편입, 재학/휴학)** 에 따라 달라진다. 학생은 공지와 규정을 읽은 뒤 "그래서 **나**한테는 뭐가 적용되지?"를 스스로 대조해야 한다.

**사례 ① 졸업학점 — 학번과 대학에 따라 총 학점이 다르다**
같은 서울캠퍼스 이중전공 학생이라도, 2025학년도 이후 입학생(사범대학 제외)은 총 **126학점**이고 2015~2024학년도 입학생(사범대학·AI융합대학 제외)은 총 **134학점**이다. 사범대학이나 글로벌캠퍼스 일부 대학은 또 다른 기준(134~150학점)을 따른다. *(출처: 졸업이수학점 배분표)*

**사례 ② 이중전공 신청 — 대상과 기준이 공고마다 세부적으로 다르다**
「2026-2학기 이중전공 신청 일정 공고」(2026.11.05)를 보면 신청 대상은 **2026-2학기를 두 번째 학기로 재학 중인 2학년 진급 예정자**와 **2026년도 후기 편입생**이다. 신청 기간은 **11.24(화) 10시 ~ 11.30(월) 16시**이며, 기간 내에 신청하지 않거나 탈락하면 다음 학기부터 일반 신청은 할 수 없다. 이후에는 *본인 학번대에 여석이 있는 경우에만* 변경 신청이 가능하다.
우선배정 학점 기준은 자료마다 다르게 적혀 있다. 학사정보 '이중전공' 안내에는 **34학점(25학번 이후 32학점)** 으로, 2026-2 공고에는 **34학점**으로 되어 있다. 어느 쪽이 맞는지는 담당 부서 확인이 필요하다. 공식 자료만 읽고도 학생이 자기 기준을 확정하기 어려운 실제 사례다.

**사례 ③ 마감이 같은 시기에 몰리고, 내 해당 여부는 따로 확인해야 한다**
2026년 11월 말 한 주에 이중전공 신청(11.24~30), 겨울 계절학기 수강신청(11.25~27), 창업장학금·HUFS Dream 장학금(글로벌) 신청 마감(~11.27)이 겹친다. 일정 자체는 공지되지만, 각각이 **나에게 해당하는지, 어떤 추가 조건이 있는지**는 학생이 공지마다 따로 확인해야 한다.

**사례 ④ 졸업 요건은 학점 외 조건까지 포함한다**
졸업하려면 학점 외에도 졸업논문 또는 졸업시험 통과, 졸업인증 및 외국어인증 통과가 필요하다. 학점을 모두 채워도 인증이 미완료이면 **수료(졸업대기)** 처리되고, 이후에는 휴학과 수강신청을 할 수 없다.

### 개선이 필요한 이유
- 정보가 없는 것이 아니라, **흩어진 공식 정보를 내 조건에 맞춰 해석하는 부담**이 학생에게 남아 있다.
- 신청 시기를 놓치면 이후 선택 기회가 여석 등에 제한되는 제도가 있어, 해석 오류의 비용이 크다.
- 같은 유형의 문의가 매 학기 반복되어 학사종합지원센터와 학과 사무실의 부담도 커진다.

## 3. 서비스 개요 및 차이점

### 서비스 개요

> 사용자가 입학년도, 캠퍼스, 소속 대학·학과, 현재 이수학기, 학적 상태와 전공 이수 유형을 처음 한 번 등록하면, 이후 질문마다 이 정보를 반영해 **개인에게 적용되는 학사 규정과 필요한 절차**를 안내하는 한국외대 맞춤 학사 챗봇이다. 같은 질문에도 학생별 적용 규정에 따라 답변과 근거를 다르게 제공하며, 판단에 필요한 정보가 부족하거나 공식 자료가 서로 충돌하면 **추측하지 않고** 추가 질문을 하거나 담당 부서 확인으로 연결한다.

### 핵심 기능 (본선 구현)

**① 프로필 등록·저장·수정**
- 저장 항목: 입학년도, 캠퍼스(서울/글로벌), 소속 대학·학과, 현재 이수학기, 학적 상태(신입학/편입, 재학/휴학), 전공 이수 유형(이중전공/부전공/전공심화+부전공/전공심화/**미정**)
- 학번 전체, 실명, 성적은 받지 않는다. 1학년은 이수 유형이 정해지지 않았을 수 있으므로 '미정'을 허용한다.
- 사용자는 언제든 프로필을 확인·수정·삭제할 수 있다.

**② 프로필을 반영한 학사 Q&A**
- 질문을 해석해 그 질문에 **필요한 개인 조건만** 골라 적용한다. 예를 들어 졸업학점 질문에는 캠퍼스·입학년도·대학·이수 유형을 쓰고, 휴학 질문에는 학적 상태와 이수학기를 쓴다.
- 답변 앞에 학과명을 붙이는 정도가 아니라, **적용 규정 자체가 달라지는 개인화**를 목표로 한다.
- 대화 맥락을 유지한다: "그럼 부전공으로 바꾸면?", "신청은 어디서 해?"처럼 이어서 물어도 조건과 주제를 이어받는다.

**③ 적용 근거 표시**
모든 답변에 다음을 함께 보여준다.
- **적용한 내 조건** (예: "서울캠퍼스 · 2026학번 · 비사범대 · 이중전공 기준")
- 관련 규정 요약과 **원문 링크**, **확인 기준일**
- 해당하는 경우 신청 기간·신청 경로(예: 종합정보시스템 → 전공/교직관리 → 이중전공 신청)

**④ 정보 부족·예외 처리**
- 판단에 필요한 정보가 없으면 **그때 묻는다** (예: 이수학점, 편입 여부). 입력받지 않은 정보를 추측해 답에 쓰지 않는다.
- 공식 자료끼리 충돌하면 한쪽을 골라 단정하지 않는다. 충돌 내용을 그대로 보여주고 문의할 부서와 연락처를 안내한다.
- **가정 질문 분리**: "내 친구가 2024학번이면?"처럼 다른 조건을 묻는 질문은 그 답변에만 적용하고, 저장된 프로필을 덮어쓰지 않는다. 프로필 수정은 별도 동작으로만 한다.
- **안내와 판정 구분**: 사용자가 입력한 정보에 기반한 안내이며, 학교의 공식 학적·졸업 판정과는 별개임을 표시한다.

### 본선 지원 범위
1인·3주 개발이므로, 검증된 데이터로 정확도를 보장할 수 있는 영역부터 지원한다.

| 지원 영역 | 내용 |
|---|---|
| 졸업학점 | 캠퍼스·입학년도·대학·이수 유형별 졸업학점 배분표 (총 학점과 영역별 최소 학점 안내. 실제 졸업 가능 여부는 판정하지 않음) |
| 이중전공·부전공 | 신청 대상·기간·방법, 우선배정 기준, 캠퍼스 간 제한 학과, 변경 신청 |
| 휴·복학 | 신청 시기, 신·편입생 1학기 휴학 제한, 휴학 기간 한도 |

지원 범위 밖의 질문(예: 학과별 전공필수, 장학 선발)에는 "현재 지원하지 않는 영역"임을 밝히고 공식 페이지나 담당 부서로 안내한다.

### 후속 기능 (본선 이후 로드맵)
- 챗봇이 안내한 신청 기간을 내 일정으로 저장하고 D-day 안내
- 지원 영역 확대(교환학생·파견, 조기졸업, 외국어인증, 장학 조건)
- 학년별 로드맵·졸업요건 진행률
- 참여 유도를 위한 게이미피케이션(목표를 달성하면 성장하는 '캠퍼스 펫') — 정식 배포 단계에서 검토

### 기존 서비스와의 차이

교내에는 이미 학사 챗봇 **훕또기**와 학교 앱 PUSH·알림톡 발송 시스템(**UMS**)이 있다. 아래 비교는 훕또기의 **공개 화면과 릴리즈노트에서 확인한 범위**만을 기준으로 하며, 비공개 내부 기능까지 단정하지 않는다.

| 비교 항목 | 기존 서비스에서 확인한 범위 | 외대 놓침방지 |
|---|---|---|
| 학사 질의응답 | 공개 학사 자료를 근거로 답변 | 저장된 캠퍼스·입학년도·대학·이수 유형을 질문마다 자동 반영해 **적용 규정 자체를 좁힘** |
| 조건 입력 | 맞춤 장학금 찾기에서 조건을 입력받으며, 입력 조건은 저장하지 않는다고 안내 | 처음 등록한 프로필을 **여러 대화와 학사 주제에 재사용** — 매번 다시 설명할 필요 없음 |
| 날짜 안내 | 공지 마감 D-day 안내 제공 | 기간과 함께 **내가 대상인지, 어떤 추가 조건이 필요한지**를 설명 |
| 불확실성 처리 | 장학금 조건을 신청 가능·확인 필요·해당 없음으로 구분 | 같은 원칙을 학사 상담 전반에 적용하고, 자료 충돌을 명시적으로 드러냄 |
| 알림 발송 | UMS로 대상자 PUSH·알림톡 발송 | 새 알림 채널을 만들기보다, 개인 조건 해석 결과를 UMS 등 기존 채널과 연계하는 방향을 정책화 단계에서 제안 |

**한 줄 차별점**: 개인화 기능이 있느냐가 아니라, **한 번 등록한 내 학사 프로필을 모든 학사 질문에 계속 적용하고, 모르는 것은 모른다고 말하는 상담 경험**이다.

## 4. 생성형 AI 및 바이브코딩 활용 계획

### 답변 생성 흐름

```
질문 + 저장 프로필
  → ① 질문 해석: 주제와 필요한 개인 조건 판별 (AI)
  → ② 조건 확인: 부족하면 추가 질문, 가정 조건이면 이번 답변에만 적용
  → ③ 근거 검색: 개인 조건에 맞는 공식 자료만 검색 (메타데이터 필터 + 검색)
  → ④ 규정 대조: 검증된 규정 데이터·로직으로 수치·자격 계산, 자료 충돌 감지
  → ⑤ 답변 생성: 개인화 설명 + 적용 조건 + 출처·기준일 (AI)
```

### AI와 규칙의 역할 분담

| 역할 | 담당 | 이유 |
|---|---|---|
| 질문 의도 파악, 필요한 조건 판별, 후속 질문 맥락 유지 | **HyperCLOVA X (CLOVA Studio)** | 자연어 해석이 필요한 영역 |
| 관련 근거 검색 | CLOVA Studio 임베딩 + 메타데이터 필터 | 입학년도 범위·캠퍼스·대학·시행 시점으로 먼저 걸러야 다른 학번의 규정이 섞이지 않음 |
| 졸업학점 수치, 신청 자격, 기간 계산 | **검증된 규정 데이터 + 코드 로직** | AI가 학점이나 자격 기준을 지어내지 않도록 함 |
| 자료 충돌 감지 | 규정 데이터에 충돌 표시 + 로직 | 최신 게시일이라는 이유만으로 자동으로 덮어쓰지 않음 |
| 설명 문장 생성 | HyperCLOVA X | 확정된 근거만 넣어 쉬운 문장으로 설명 |

### 공식 자료의 구조화
각 규정·공지 조각에 다음 메타데이터를 붙인다: **적용 입학년도 범위, 캠퍼스, 적용 대학·학과, 대상 학적(신입/편입), 시행 학기, 원문 링크, 확인일**. 학년만으로 대상을 고정하지 않는다. 학년만 보면 편입생이나 휴·복학생 사례를 틀리기 쉽다.

### 데이터 갱신
본선 기간에는 개발자가 공지를 직접 확인해 규정 데이터를 갱신하고 검수한다. 정식 운영에서는 담당 부서가 갱신을 확인하는 절차를 둔다(6번 항목 참조).

### 바이브코딩 활용
1인 개발자가 AI 코딩 에이전트(Claude Code 등)를 협업자로 활용한다. 결과보고서에는 도구 이름만 쓰지 않고 **요구사항 프롬프트 → 생성 코드 검토 → 오류 발견 → 수정·검증**의 실제 사례를 기록해, AI가 만든 코드를 어떻게 통제했는지 보여준다.

## 5. 구현 계획 및 실현 가능성

### 본선 결과물
- 실제 접속 가능한 **모바일 우선 웹 챗봇**: 프로필 등록·수정 → 개인화 Q&A → 근거 표시 → 예외 처리
- 지원 3개 영역(졸업학점·이중전공·휴복학)의 검수된 규정 데이터
- 개인화 정확도 시험 세트와 평가 결과
- 시연: 같은 질문을 서로 다른 프로필에서 보여주는 시나리오

### 현재 진행 상황 (2026.11.09 기준 프로토타입)

아래 수치는 이미 달성한 성과가 아니라 **목표**이며, 개발 중 결과를 보고 확정한다.

|---|---|
| 개인 조건 반영 | 프로필·질문 조합 20~30개를 만들고, 적용 규정과 근거를 사람이 미리 정리해 비교 |

### 예상 어려움과 대응

| 예상 어려움 | 대응 |
|---|---|
| AI가 학점·자격 기준을 지어냄 | 수치와 자격은 검증된 데이터·로직으로만 계산하고, AI는 해석과 설명만 담당 |
| 공식 자료 간 충돌 | 단정하지 않고 충돌을 표시한 뒤 담당 부서 문의 안내 |

| 가정 질문이 프로필을 오염시킴 | 이번 답변에만 쓰는 조건과 저장 프로필 수정을 분리 |
| 1인 개발의 작업량 | 지원 영역을 3개로 제한하고, 나머지는 로드맵으로 분리 |
| 개인정보 | 아래 '개인정보 처리' 참조 |

### 개인정보 처리
- **수집하는 것**: 입학년도, 캠퍼스, 대학·학과, 이수학기, 학적 상태, 이수 유형. 이수학점은 필요한 질문에서만 선택 입력받는다.
- **수집하지 않는 것**: 학번 전체, 실명, 성적표.
- **저장 위치**: 프로필은 사용자 기기의 브라우저에 저장한다. 답변 생성을 위해 질문과 필요한 프로필 항목이 CLOVA Studio API로 전송된다.
- **대화 기록**: 본선에서는 서버에 장기 저장하지 않는다. 평가용 로그는 동의한 테스트 참여자에 한해 익명으로 수집한다.
- **삭제**: 앱 안의 '내 정보 삭제'로 즉시 삭제할 수 있다.

## 6. 기대효과

### 단기 효과 (본선에서 검증할 것)
- **질문 해결 시간 단축**과 **재입력 감소**: 저장된 프로필 덕분에 매번 조건을 다시 설명하지 않아도 된다.
- **개인 조건 적용 품질**: 같은 질문에도 학생별로 맞는 규정이 적용되며, 모르는 부분은 추측하지 않는다.

### 장기 기대효과 (정식 운영 시)
- 신청 대상·기간을 잘못 이해해 생기는 기회 손실 감소
- 반복 문의 감소로 학사종합지원센터와 학과 사무실의 부담 완화
- 이중전공·교환학생 등 외대 강점 제도를 학생들이 제때 활용

### 교내 활용 가능성 (정책화)
- **근거 데이터 갱신**: 학사종합지원센터가 학기마다 규정·공지 변경을 확인하고, 정보처가 데이터 연동을 지원하는 운영 구조를 제안한다.
- **오답 정정 절차**: 답변마다 '틀렸어요' 신고 기능을 두고, 신고된 항목은 담당 부서 검토 후 규정 데이터를 수정한다.
- **담당 부서 연결**: 지원 범위 밖 질문이나 자료 충돌은 해당 부서 연락처로 안내해 상담 창구의 1차 분류 역할을 한다.
- **기존 시스템과의 연계**: 훕또기의 학사 Q&A에 '저장 프로필' 기능을 더하는 형태, 또는 UMS 알림 대상 선정에 개인 조건 해석을 활용하는 형태로 확장할 수 있다.
- **운영 주체**: 정식 운영 시 정보처(시스템)와 학사종합지원센터(내용 검수)의 공동 운영을 제안한다.

### 첫 적용 대상과 사용자 규모
- **본선 시험**: 외대생 10~15명 사용자 테스트 + 프로필·질문 시험 세트 20~30개
- **첫 적용 대상**: 이중전공 신청을 앞둔 1학년과 후기 편입생(규정 차이가 크고 신청 시기가 정해져 있음)
- **확대**: 지원 영역을 넓히면서 졸업요건을 점검하는 고학년, 휴·복학생으로 확대
